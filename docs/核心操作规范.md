# 发布的任务/参与的任务 页面核心操作规范 
# 页面路径：pages\ucenter\myTasks\joined.vue  pages\ucenter\myTasks\published.vue

## 1. 页面：我参与的任务（joined.vue） & 我发布的任务（published.vue）

### 1.1 数据加载与刷新
- 支持下拉刷新（onPullDownRefresh）：重置页码，强制拉取第一页数据，更新缓存快照。
- 支持触底加载（onReachBottom）：页码+1，拉取下一页数据，追加到列表。
- 首次加载/切换筛选条件时，优先命中缓存快照（1分钟有效，按筛选条件和分类分组）。
- 缓存快照结构：{ ts, data: { tasks, hasMore, pagination } }，每个筛选条件/分类独立缓存。

### 1.2 左滑操作（uni-swipe-action）
- 支持操作：
  - 编辑（仅发布者/未开始，跳转 publish.vue，调用 updateTask 云函数）
  - 删除/退出：
    - 未开始、已失效、已评价：
      - 仅参与：显示“退出”按钮
      - 发布并参与/发布者：显示“删除”按钮
    - 其他状态（如已完成未评价、进行中）：不显示删除/退出按钮
  - 评价（已完成，未评价，右滑弹出评价抽屉，调用 rateTask 云函数）
  - 查看评价（已评价，右滑弹出只读评价抽屉）

### 1.3 操作逻辑与云函数
- **数据获取**：
  - getMyPublishedTasks（published.vue）
  - getMyJoinedTasks（joined.vue）
- **编辑任务**：
  - 跳转 publish.vue，带 id 和 edit=1 参数
  - 调用 updateTask 云函数，更新 kl-tasks 表
- **删除/退出任务**：
  - 调用 deleteMyTask 云函数，见本规范前述详细逻辑
  - 影响 kl-tasks（主表）和 kl-users-join-task（关系表）
- **评价任务**：
  - 右滑“评价”按钮，弹出评价抽屉，填写评分和内容，调用 rateTask 云函数，更新 kl-users-join-task 表
- **查看评价**：
  - 右滑“查看评价”按钮，弹出只读评价抽屉，展示评分、内容、时间

### 1.4 页面跳转
- 编辑：跳转 publish.vue
- 评价/查看评价：弹出抽屉，无页面跳转
- 详情：点击卡片跳转 detail.vue

### 1.5 影响的数据表
- kl-tasks：任务主表（编辑、删除、参与人数变更等）
- kl-users-join-task：任务参与关系表（退出、评价、软删除等）

### 任务删除/退出核心操作规范
### 1.6 发布者删除
- **未开始**：主表软删除并参与人数清零，所有参与关系软删除且状态设为 removed。
- **已完成/已失效**：主表软删除，所有参与关系软删除且状态设为 removed。
- **进行中**：禁止删除，返回错误提示。

### 1.7 参与者退出
- **未开始**：主表参与人数减1，自己参与关系软删除且状态设为 quit。
- **已完成/已失效**：自己参与关系软删除且状态设为 deleted。
- **进行中**：禁止删除，返回错误提示。

### 1.8 任务计数更新规范
#### 1.8.1 计数字段
- `store.userInfo.publishedCount`：用户发布的任务数量（未软删除）
- `store.userInfo.joinedCount`：用户参与的任务数量（未软删除）

#### 1.8.2 更新时机
- **页面进入**：`ucenter.vue` 的 `onShow` 生命周期调用 `publishAndJoinedCounts` 云函数
- **发布任务**：`publishTask` 云函数成功后返回 `publishedCount`，前端更新 `store.userInfo.publishedCount`
- **加入任务**：`joinTask` 云函数成功后返回 `joinedCount`，前端更新 `store.userInfo.joinedCount`
- **删除/退出任务**：`deleteMyTask` 云函数成功后返回 `publishedCount` 和 `joinedCount`，前端同时更新两个计数
- **开始任务**：`startTask` 云函数成功后返回 `score`，前端更新 `store.userInfo.score`

#### 1.8.3 云函数返回格式
```javascript
// 成功时返回格式
{
  code: 0,
  message: '操作成功',
  publishedCount: 5,  // 发布任务数量
  joinedCount: 3,     // 参与任务数量
  score: 100          // 积分余额（开始任务时返回）
}
```

#### 1.8.4 前端更新逻辑
```javascript
// 在相关操作成功后更新计数
// 错误方式：直接赋值（不会持久化）
// store.userInfo.publishedCount = res.result.publishedCount;

// 正确方式：使用 mutations.setUserInfo 方法（会持久化到本地存储）
if (res.result.publishedCount !== undefined) {
  mutations.setUserInfo({ publishedCount: res.result.publishedCount });
}
if (res.result.joinedCount !== undefined) {
  mutations.setUserInfo({ joinedCount: res.result.joinedCount });
}
```

**重要提醒**：所有涉及 `store.userInfo` 数据更新的地方都必须使用 `mutations.setUserInfo()` 方法，而不是直接赋值。这样可以确保数据持久化到本地存储，避免页面重新加载时数据丢失。

#### 1.8.5 角标显示
- 在 `ucenter.vue` 的网格项中使用官方 `uni-badge` 组件
- 使用 `absolute="rightTop"` 定位到右上角
- 使用 `type="error"` 红色样式，`size="small"` 小尺寸
- 当计数为 0 时角标会自动隐藏
- 组件会自动处理数字显示和样式

### 1.9 发布者兼参与者的特殊处理
#### 1.9.1 按钮显示逻辑
- **发布者兼参与者**：只显示"确认完成"或"查看进度"按钮，默认自己的任务已完成
- **仅参与者**：显示"标记完成"按钮
- **仅发布者**：显示"结束任务"或"查看进度"按钮

#### 1.9.2 完成状态检查
- 检查所有参与者完成状态时，排除发布者自己
- 如果只有发布者自己参与，直接认为可以结束任务
- 发布者结束任务时，不给自己发放奖励积分

#### 1.9.3 积分更新
- 结束任务成功后，返回发布者的最新积分余额
- 前端使用 `mutations.setUserInfo({ score: newScore })` 更新积分
- 确保积分更新持久化到本地存储

#### 1.9.4 云函数逻辑
- 当只有发布者自己参与时，直接允许结束任务
- 当有其他参与者时，需要所有参与者都完成才能结束
- 发布者不给自己发放奖励积分

### 1.10 进度查看弹窗规范
- **触发方式**：发布者点击"查看进度"按钮
- **显示内容**：
  - 任务基本信息（名称、状态）
  - 参与者列表（头像、昵称、角色、状态）
  - 状态图标（进行中：旋转图标，已完成：对勾图标）
- **操作按钮**：
  - **刷新进度**：重新获取最新进度数据
  - **结束任务**：结束整个任务（仅当所有参与者完成时可用）
  - **关闭**：关闭弹窗，返回任务列表
- **状态显示**：
  - 进行中：蓝色旋转图标 + "进行中"文字
  - 已完成：绿色对勾图标 + "已完成"文字
  - 其他状态：显示对应状态文字
- **按钮状态**：
  - 结束任务按钮：所有参与者完成时可用，否则禁用
  - 刷新进度按钮：始终可用
  - 关闭按钮：始终可用

### 1.11 任务状态流转规范
#### 1.11.1 参与者标记完成
- 参与者点击"标记完成"按钮
- 只更新 `kl-users-join-task` 表中该参与者的状态为 `finished`
- 不更新主任务状态，任务仍为 `in_progress`
- 前端更新本地缓存中的 `myJoinStatus` 为 `finished`

#### 1.11.2 发布者确认完成
- 发布者点击"确认完成"或"结束任务"按钮
- 更新所有参与者的状态为 `finished`
- 更新主任务状态为 `finished`
- 给所有参与者发放奖励积分（不包含发布者自己）
- 返回发布者的最新积分余额

#### 1.11.3 状态流转逻辑
- **参与者标记完成**：个人状态 `joined` → `finished`，任务状态不变
- **发布者确认完成**：所有参与者状态 → `finished`，任务状态 `in_progress` → `finished`
- **只有发布者参与**：直接完成任务，状态 `in_progress` → `finished`

#### 1.11.4 缓存更新机制
- 任务状态变更后，立即更新本地任务列表缓存
- 更新所有页面缓存快照中的任务状态
- 重新计算分类选项的计数
- 确保UI状态与数据库状态同步

### 1.12 云函数修复规范
#### 1.12.1 endTask 云函数完善
- **功能**：发布者结束任务，更新所有参与者状态
- **权限检查**：确保只有发布者可以操作
- **状态更新**：
  - 更新所有 `kl-users-join-task` 记录状态为 `finished`
  - 更新主任务状态为 `finished`
  - 设置 `finish_time` 和 `end_time` 时间戳
- **奖励发放**：给所有非发布者参与者发放积分奖励
- **返回值**：包含 `score`（发布者积分）和 `taskStatus: 'finished'`

#### 1.12.2 markTaskFinished 云函数优化
- **功能**：参与者标记个人任务完成
- **权限检查**：确保只有参与者（非发布者）可以操作
- **状态更新**：只更新参与者个人状态为 `finished`
- **限制**：不更新主任务状态，任务仍为 `in_progress`
- **错误码**：
  - `code: 4`：发布者不能标记完成
  - `code: 5`：未找到参与关系
  - `code: 6`：参与者状态不正确

### 1.13 前端状态管理规范
#### 1.13.1 状态更新方法
- **updateTaskStatusInCache(taskId, newStatus)**：
  - 更新当前页面任务状态
  - 更新所有缓存快照中的任务状态
  - 更新参与者的 `myJoinStatus`
  - 重新计算分类选项计数

#### 1.13.2 分类选项更新
- **updateFilterOptions()**：
  - 重新计算各状态的任务数量
  - 更新分类选项显示文本
  - 确保计数与实际任务状态一致

#### 1.13.3 状态流转处理
- **参与者标记完成**：
  - 调用 `markTaskFinished` 云函数
  - 更新本地 `myJoinStatus` 为 `finished`
  - 不更新任务主状态
- **发布者确认完成**：
  - 调用 `endTask` 云函数
  - 更新任务状态为 `finished`
  - 更新发布者积分
  - 刷新任务列表和分类计数

#### 1.13.4 任务状态变更后的分类移动处理
- **handleTaskStatusChange(taskId, oldStatus, newStatus)**：
  - 处理任务状态变更后的分类移动逻辑
  - 更新所有缓存中的任务状态
  - 重新计算分类选项计数
  - 当有筛选条件时自动刷新任务列表
  - 确保任务从"进行中"正确移动到"已完成"分类

#### 1.13.5 缓存更新机制优化
- **状态变更触发**：任务状态从 `in_progress` 变为 `finished` 时
- **分类移动**：任务从"进行中"分类移除，添加到"已完成"分类
- **缓存同步**：更新所有页面缓存快照中的任务状态
- **UI刷新**：重新计算分类计数，更新筛选选项显示
- **条件刷新**：当用户当前有筛选条件时，自动重新加载数据

### 1.14 数据库状态同步规范
#### 1.14.1 kl-users-join-task 表更新
- **参与者标记完成**：`status: 'joined'` → `status: 'finished'`
- **发布者确认完成**：所有记录 `status: 'finished'`
- **时间戳**：设置 `finish_time` 字段

#### 1.14.2 kl-tasks 表更新
- **发布者确认完成**：`status: 'in_progress'` → `status: 'finished'`
- **时间戳**：设置 `end_time` 字段

#### 1.14.3 uni-id-scores 表更新
- **奖励发放**：给所有非发布者参与者添加积分记录
- **类型标识**：`type: 5`（任务完成奖励）
- **积分计算**：每人获得任务设定的积分奖励

### 1.15 状态流转优化规范
#### 1.15.1 状态字段统一
- **参与者状态**：
  - `preJoin`：加入未就绪
  - `ready`：已就绪
  - `in_progress`：进行中（原 joined）
  - `finished`：已完成（原 completed）
  - `evaluated`：已评价
- **任务状态**：
  - `not_started`：未开始
  - `in_progress`：进行中
  - `finished`：已完成
  - `invalid`：已失效

#### 1.15.2 状态流转逻辑
- **发布者加入**：`preJoin`（加入未就绪）
- **任务开始**：`ready` → `in_progress`（参与者），`preJoin` → `in_progress`（发布者）
- **参与者完成**：`in_progress` → `finished`
- **任务结束**：所有参与者 `finished` 后，任务状态变为 `finished`

#### 1.15.3 云函数更新
- **joinTask**：发布者加入时状态设为 `preJoin`（加入未就绪）
- **startTask**：
  - 参与者状态从 `ready` 流转为 `in_progress`
  - 发布者状态从 `preJoin` 流转为 `in_progress`（如果发布者也是参与者）
- **markTaskFinished**：参与者状态从 `in_progress` 流转为 `finished`
- **endTask**：检查参与者状态是否为 `finished`

### 1.16 分类角标显示规范

#### 1.16.1 功能概述
在"我发布的任务"和"我参与的任务"页面的分类标签上显示任务数量角标，提供直观的数量统计信息。

#### 1.16.2 角标显示规则
- **显示位置**：每个分类标签的左侧
- **显示内容**：该分类下的任务数量
- **显示条件**：数量大于0时显示，为0时隐藏
- **样式**：使用 `uni-badge` 组件，红色背景，小尺寸

#### 1.16.3 数据更新时机
- **初次加载**：页面加载时从云函数获取各分类数量
- **下拉刷新**：刷新时重新获取最新数量
- **切换分类**：切换时从缓存或重新获取数量
- **操作后更新**：删除、退出、发布、加入任务后更新相关分类数量

#### 1.16.4 云函数返回格式
```javascript
{
  code: 0,
  data: [...],
  hasMore: true,
  page: 1,
  pageSize: 10,
  total: 25,
  categoryCounts: {
    '全部': 25,
    '待开始': 8,
    '进行中': 12,
    '已完成': 3,
    '已失效': 1,
    '已评价': 1
  }
}
```

#### 1.16.5 前端实现要点
- 使用 `categoryCounts` 数据属性存储各分类数量
- 在模板中使用 `uni-badge` 组件显示数量
- 缓存中包含分类数量信息，确保切换分类时快速显示
- 角标样式根据分类激活状态动态调整

#### 1.16.6 样式规范
- 角标位置：分类标签左侧，距离文字4px
- 角标大小：small尺寸
- 角标颜色：error类型（红色）
- 激活状态：半透明白色背景，白色文字
- 非激活状态：默认红色背景

#### 1.16.7 分类统计逻辑优化

**问题分析**：
- 原统计逻辑使用复杂的聚合查询，容易出错
- "全部"分类的统计逻辑有误，会重复应用过滤条件
- extra过滤逻辑在统计时应用不当

**修复方案**：
1. **简化查询逻辑**：使用简单的 `where` 查询获取任务列表和参与状态
2. **内存中统计**：在JavaScript中进行分类统计，避免复杂的聚合查询
3. **正确的extra过滤**：根据用户角色（发布者/参与者）正确应用过滤条件

**统计逻辑**：
- **我参与的任务**：
  - 获取用户参与的所有任务ID
  - 根据任务状态和用户参与状态分类
  - 支持"仅我参与的"和"我发布并参与的"过滤
- **我发布的任务**：
  - 获取用户发布的所有任务
  - 检查用户是否也参与了这些任务
  - 支持"仅发布的"和"发布并参与的"过滤

**分类规则**：
- **待开始**：`task.status === 'not_started'`
- **进行中**：`task.status === 'in_progress'`
- **已完成**：`task.status === 'finished'` 且 `userJoin.status !== 'evaluated'`
- **已评价**：`task.status === 'finished'` 且 `userJoin.status === 'evaluated'`
- **已失效**：`task.status === 'invalid'`

#### 1.16.8 角标位置优化

**问题分析**：
- 角标显示在文本前方或后方，不符合设计需求
- 用户希望角标显示在文本的右上角

**修复方案**：
1. **使用absolute定位**：设置 `absolute="rightTop"` 让角标显示在右上角
2. **添加偏移量**：使用 `:offset="[-3, -3]"` 微调角标位置
3. **保持激活状态样式**：确保激活状态下文本颜色为白色

**实现要点**：
- 使用 `uni-badge` 包裹文本内容
- 当数量为0时，直接显示文本，不显示角标
- 保持原有的激活状态样式和过渡效果

**样式规范**：
- 角标位置：`absolute="rightTop"`
- 偏移量：`offset="[-3, -3]"`
- 激活状态：白色文本，半透明白色角标背景
